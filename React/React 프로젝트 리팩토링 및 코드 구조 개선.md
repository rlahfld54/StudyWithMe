# React 프로젝트 리팩토링 및 코드 구조 개선

React는 컴포넌트와 상태 관리 방식에 대한 자유도가 높지만, 구조를 제대로 설계하지 않으면 코드가 복잡해지고 유지보수가 어려워질 수 있습니다.

개발 경험이 부족한 상태에서 기능을 계속 추가하다 보면 중복 코드가 발생하거나 컴포넌트의 책임이 불분명해질 수 있습니다. 개인적으로는 이러한 이유로 React보다 Vue.js를 선호합니다.

프로젝트 개발 과정에서 AI를 활용했지만, 기능을 추가하거나 수정하는 과정에서 기존 코드의 구조와 의도를 충분히 반영하지 못하는 경우가 있었습니다.

현재 제 React 이해도 역시 충분하지 않다고 판단하여, 기존 프로젝트를 리팩토링하면서 React의 동작 원리와 올바른 사용 방법을 다시 학습하기로 했습니다.

## 1. React 상태 관리 구조 개선 및 불필요한 useEffect 제거

저는 화면단 코드를 작성할 때 컴포넌트의 라이프사이클과 데이터 흐름을 먼저 파악합니다.
먼저 App.jsx를 확인한 결과, useEffect가 7개 사용되고 있었습니다.
6개월동안 여러 기능이 추가되고 삭제되며 더 이상 사용하지 않는 코드였습니다.
아직까지는 삭제후에도 오류없이 잘 돌아갔습니다.

AI가 무분별하게 코드를 입력해 놓아서 직접 다 수정하기 막막하여 기능별로 분리해 정리해달라고 요청하였습니다.

## 2. 공통 CSS 및 프로젝트 구조 정리

기존 프로젝트에서는 공통 CSS를 사용하고 있었지만, 개발 과정에서 일부 공통 스타일이 사라지거나 개별 컴포넌트에 분산되어 있었습니다.

이로 인해 동일한 스타일을 여러 곳에서 관리해야 하는 문제가 발생했습니다.

공통으로 사용되는 스타일을 다시 정리하고, 컴포넌트별 스타일과 구분하는 작업을 진행하고 있습니다.

또한 AI를 이용해 코드를 수정하는 과정에서 이전에 개선한 코드가 다시 변경되거나 원래 구조로 돌아가는 경험도 있었습니다.

이를 방지하기 위해 React 공식 문서를 참고하여 프로젝트의 개발 원칙과 코드 작성 기준을 정리하고, AI가 작업할 때 참고할 수 있도록 프로젝트 내부에 문서로 저장했습니다.

AI가 기존 코드의 의도와 프로젝트 구조를 최대한 유지하면서 작업할 수 있도록 하기 위한 목적입니다.

## 3. React 공식 문서를 통한 학습

오랜만에 React를 다시 살펴보면서 기존에 알고 있던 사용 방식과 현재 공식 문서에서 권장하는 방식에 차이가 있다는 것을 확인했습니다.

특히 useEffect를 중심으로 상태 변경과 라이프사이클을 처리했던 기존 접근 방식에서 벗어나, 각 Hook의 역할과 사용 목적을 구분할 필요가 있다고 느꼈습니다.

useEffect 외에도 useMemo, useCallback, useReducer, useRef 등 다양한 Hook의 역할과 활용 방법을 다시 학습하고 있습니다.

과거 Vue.js를 사용했던 경험과 비교해 보니 현재 프로젝트는 상태 관리와 컴포넌트 구조가 체계적으로 정리되지 않은 상태였습니다. 상황에 적합한 Hook을 충분히 활용하지 못했다는 점에서도 아쉬움이 남았습니다.

오랜 개발 공백으로 인해 제 개발 역량에 대한 의구심도 있었지만, 공식 문서와 관련 자료를 찾아보니 이전에 학습했던 개념들이 다시 떠올랐습니다. 기본적인 개념을 완전히 잊은 것은 아니라는 점에서 조금은 안도할 수 있었습니다.

이번 기회를 통해 단순히 Hook의 사용법을 익히는 데 그치지 않고, 각 기능이 필요한 이유와 적절한 활용 시점을 이해하는 데 집중하려고 합니다.
